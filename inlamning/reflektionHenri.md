2. Vad går sönder utan automation?

Jag har valt att reflektera över M8, alltså Terraform-delen. Det största värdet med Terraform är att infrastrukturen beskrivs i kod och därför kan återskapas exakt likadant, när som helst och av vem som helst i teamet. Det är viktigt när man behöver en robust server som snabbt ska kunna sättas upp och rivas ner. Det finns ingen "this works on my machine" om terraform används.

När vi arbetade med Terraform i par märkte vi hur snabbt man kan bygga upp och riva ett system när Terraform-filerna väl är skrivna. Vi såg också hur lätt det är att se vad en ändring gör innan den genomförs, eftersom terraform plan visar skillnaden. För en app som körs live på webben är det avgörande att det fungerar.

Om vi gick tillbaka till att göra allt för hand skulle vi inte ha något fungerande arbetsflöde för att skapa nya system. Det skulle smyga sig in små misstag, som att glömma en regel i security groupen, vilket händer när människor gör samma sak manuellt. Det tar dessutom tid, och alla som ska göra det behöver instruktioner och måste vara insatta i infrastrukturen för att göra allt rätt. Om någon gör fel vid en uppdatering kan appen sluta fungera, och då kan till exempel kunderna inte använda den. Man kan också råka ta bort fel server när man tar bort den för hand. Med Terraform automatiseras hela processen, och skydd som prevent_destroy stoppar att viktiga resurser rivs av misstag.

Slutligen gör Terraform ändringar spårbara. Eftersom infrastrukturen finns som kod syns varje ändring i filerna och kan granskas i en pull request. Om något går sönder är det därför lätt att felsöka, eftersom man vet exakt vad som har ändrats. Om infrastrukturen sköttes för hand skulle det vara mycket svårare att se vilka ändringar som har gjorts. När något går sönder kan det då ta lång tid att ens avgöra om felet ligger i koden eller i infrastrukturen, och ännu längre att förstå vad felet är och hur det ska åtgärdas. Terraform gör felsökningen snabbare, eftersom varje ändring av infrastrukturen finns i koden och man vet exakt vad som har ändrats.

Jag tyckte det var intressant att i M8-labben testa hur man kan sätta upp allting med Terraform, och jag vill definitivt använda det i egna projekt i framtiden. Det var spännande att se hur man först skriver Terraform-konfigurationen, granskar den med terraform plan och sedan låter Terraform bygga servern. Därifrån kan man skapa så många deployments som man behöver, men också riva ner allting lika snabbt utan att något blir kvar.
